- 날짜: 2026-07-22
- 대상: `love2d-codedefense` (feature/codedefense-tutorial 브랜치)
- 배경: 실플레이 피드백 — "튜토리얼 중 우상단 적 구성·좌하단 설치 로그 같은 오버레이를
  레이아웃 칼럼으로 명시적으로 빼 달라" + "내가 정의한 함수 목록 기록" + "함수 사전에

## 1. 3칼럼 레이아웃 (창 960×640 → 1280×640)

```
전장 384px │ 정보 칼럼 240px │ 에디터 ~610px
```

- **전장** (x=8): 그리드 12×16(384×512) + 상단 HUD/진행 바 유지. **오버레이 전면 제거**
  (적 구성 패널·전투 로그 오버레이 삭제) — 필드와 튜토리얼 말풍선·하이라이트가 깨끗해짐.
- **정보 칼럼** (x≈400, w=240, 위→아래):
  1. **문제 요약**: `[문제 N] concept` + `메모리 영역: theme` + "Ctrl+I 상세" 안내 (2~3줄)
  2. **적 구성**: 종류별 미니 스프라이트 + "처리 n / 전체 N" (+ 스폰 종료 후 "잔여 소탕 · 생존!")
  3. **함수 사전** (§2)
  4. **전투 로그**: 최근 8줄 상시 (기존 3줄 제한 해제)
- **에디터** (x≈656, w≈610): 기존보다 넓어짐. IDE 타이틀바·아바타·퀵바 유지.
- **문제 카드**(Ctrl+I 상세)와 튜토리얼 말풍선은 좌표 재조정 (전장+정보 칼럼 영역 기준 중앙).
- 중앙 정렬 화면들(intro/title/stageselect/result/codex)은 하드코딩 960을
  `love.graphics.getWidth()` 기반으로 교체.

## 2. 함수 사전 (정보 칼럼 섹션)

### 2.1 수록 항목

- **기본 제공(빌트인)**: `build` 1종으로 시작 — 항목 내용은 코드가 아니라 문서:
  시그니처 `build(종류, 행, 열, "이름")`, 규칙 요약(멱등 — 같은 이름 재호출은 무시 /
  예산 차감 / 건설칸(B)만 / 테크 requires / 한글 별칭 인정), 예시 한 줄.
  (다른 API 문서 항목 추가는 후속 — 데이터 구조는 확장 가능하게.)
- **유저 정의 함수**: F5 저장 성공 시 스크립트 실행 전후 env를 비교(diff)해 새로 정의된
  **함수 타입 전역**을 수집 (`on_tick`, 직접 만든 전역 함수 등). `local function`은 지역이라
  감지 불가 — 사전 하단에 작은 안내 1줄. 엔진은 `battle.userFuncs`(이름 정렬 배열)로 노출.

### 2.2 펼침 상호작용

- 사전 섹션은 평소 **이름 목록**(빌트인 `build`는 항상 첫 줄, 이후 유저 함수 정렬).
- **에디터에서 함수 이름을 마우스로 클릭**하면 사전에서 그 항목이 **펼쳐진다**:
  - 빌트인(`build`): 문서 카드(시그니처/규칙/예시).
  - 유저 함수: **현재 스크립트에서 해당 함수의 소스 발췌** — `function 이름(...)`부터
    대응하는 `end`까지 (간단한 키워드 카운팅 휴리스틱, 최대 10줄 + "…"), 정의 줄 번호 표기.
- 펼침 상태에서 다른 함수 클릭 = 항목 교체, 사전 밖 클릭 또는 ESC 아님(ESC는 나가기 유지)
  — **같은 항목 재클릭 = 접기**. 목록으로 돌아가는 명시 버튼 불필요(교체/토글로 충분).
- 에디터 클릭 판정: 가변폭 폰트이므로 클릭 픽셀 → (줄, 글자) 매핑은 폰트 측정 함수를
  **주입식**으로 받아(`Editor:charAt(px, py, measure)`) 헤드리스 테스트가 가능해야 한다.
  글자 위치에서 식별자 토큰(`[%a_][%w_]*`)을 추출해 사전 수록명과 대조.

### 2.3 영구 수집 — 도감 "내 함수" 탭

- `progress.funcbook[이름] = { first = 처음 정의한 스테이지 id, count = 정의 횟수 }` —
  F5 저장 성공 시 뷰가 누적 저장 (이름당 스테이지 1회 카운트, 같은 판 반복 저장은 미중복).
- 도감에 세 번째 탭 **[내 함수]**: 수집한 함수 이름 + "스테이지 N에서 처음 정의 · M회" —
  코딩 성장 기록. 빌트인 `build`는 이 탭이 아니라 사전 빌트인으로만.
- 기존 세이브에 funcbook 없으면 빈 테이블 보강 (호환).

## 2.5 게임 심볼 — 룩(Rook)

- 게임을 대표하는 심볼로 **체스 룩(성탑)** 픽셀아트를 제작한다 (타워 디펜스 상징) —
  `src/art.lua`에 16×16 도트(팔레트 green/cyan 계열) + 32×32 ImageData 생성.
- 적용: ① `love.window.setIcon`으로 **창/작업표시줄 아이콘** (부팅 시 1회) ② 타이틀 화면
  로고 옆/위 심볼 배치. (exe 파일 자체의 아이콘 교체는 rcedit 외부 도구가 필요해 범위 제외 —
  요청 시 후속.)

## 2.6 마우스 지원 (기본 입력화)

- **타이틀 메뉴**: 항목에 마우스 호버 시 커서 하이라이트 이동, 좌클릭으로 선택 (키보드 ↑↓+Enter 병행 유지).
- **인트로(세계관)**: 좌클릭 = Enter와 동일 (타이핑 중이면 전체 표시, 완료면 다음 장면). ESC 스킵 유지.
- **결과 화면**: 좌클릭 = Enter(스테이지 선택으로).
- **play**: 에디터 함수명 클릭(§2.2). 그 외 전장 클릭 동작은 없음(오클릭 무해).
- stageselect·codex의 목록/탭 클릭은 후속 (이번엔 키보드 유지).

## 3. 불변 조건

- 전투 코어 시뮬 로직 불변 — userFuncs 수집은 `setScript` 성공 경로에서 env 키 diff만
  (실행 결과에 영향 없음, 헤드리스 테스트). 판정 철학(§0)·결정론·샌드박스 유지.
- 기존 테스트 194개 무손상 + 신규(userFuncs diff, funcbook 왕복, Editor charAt/token 추출).

  함수 소스의 구문 강조, 다른 스테이지 함수 소스 보관(이름·통계만 수집), 에디터 호버 툴팁.
