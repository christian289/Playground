# Code Defense 신규 적·타워 (Wave B) 설계서

2026-07-23. 사용자 확정 사항(문답): 신규 적은 **IT 업계의 유명 문제 키워드**를 이름으로,
그 특징을 게임 메커니즘으로 옮긴다. 라인업 7종 + 보스 후보 확정. 진행 순서는
Wave A(완료) → **B(이 문서)** → D(셸 진영).

## 0. 설계 원칙 (Wave A에서 이어짐)

1. **밈 = 메커니즘**: 이름을 아는 개발자라면 설명 없이 특성을 예측할 수 있다.
2. **결정론 유지**: 무작위처럼 보이는 행동(은신·대시·분열)도 전부 **스폰 시각 기준 고정
   주기**다. 같은 배치·같은 코드 = 항상 같은 결과(회귀 테스트·스피드런 전제).
3. **모든 적이 코드로 풀린다**: 각 적은 특정 코딩 패턴(조건문, 표적 분산, 예측)을
   요구하는 출제 의도를 가진다. 대응법이 곧 학습 포인트다.
4. 스테이지 추가는 **데이터로만**(CSV+미로+커리큘럼+lore) — 기존 CLAUDE.md 규칙 그대로.
   신규 능력 키워드만 `src/enemy.lua`/`src/battle.lua` 코어에 추가한다.

## 1. 신규 적 7종 (enemies.csv 신규 행 + abilities 키워드)

| id | 표시명 | 유명 문제 | 메커니즘 (abilities 키워드) | 대응법 = 학습 포인트 |
|---|---|---|---|---|
| memory-leak | 메모리 릭 | Memory Leak | `grow`: 생존 1초마다 최대 HP +2 (상한: 초기값 ×5). 초저속 | 오래된 적 먼저 — `e.age` 비교/`world.oldest()` 타겟팅. 릭은 조기에 잡는다 |
| deadlock | 데드락 | Deadlock | `pair`: 항상 2기 쌍 스폰(타임라인 count=2·interval=0 이벤트). 쌍 둘 다 생존 시 받는 데미지 60% 감소 | 한 놈만 패면 안 풀린다 — 타워 2기의 표적을 이름별로 분산 |
| heisenbug | 하이젠버그 | Heisenbug | `phase`: 스폰 시각 기준 3초 관측 가능 / 2초 은신 반복. 은신 중 `world.enemies()`에서 제외 + 무적 | 보일 때만 쏜다 — nil 체크·조건문. "관측하려 하면 사라진다" |
| fork-bomb | 포크 밤 | Fork Bomb | `split2`: 사망 시 HP 절반 2기로 분열, 분열체도 1회 더 분열(총 4기, 깊이 2 제한). 기존 `split`(깊이 1)의 상위종 | 처리량 싸움 — 광역 타워(GC 수집기)의 존재 이유. `:(){ :|:& };:` |
| race-cond | 레이스 컨디션 | Race Condition | `dash`: 스폰 시각 기준 1.5초마다 0.3초 대시(이동 속도 3배). 경로는 기존 플로우 필드 그대로 | 리드샷/예측 — `e.speed`와 `bullet_speed`로 예측 표적 함수 작성 |
| legacy | 레거시 코드 | Legacy Code | `resist:printer`: 프린터 계열 데미지 50% 저항. 초고HP·초저속 탱커 | "아무도 건드리려 하지 않는다" — 스나이퍼(전문가 투입) 테크 체인 필수 |
| ddos-bot | DDoS 봇 | DDoS | 능력 없음. HP 5·초고속 잡몹. 특징은 **타임라인 패턴**: 한 이벤트 30기 융단 러시 | 단일 고화력보다 연사·광역 배치. 진행 바 눈금이 새빨개지는 것 자체가 예고 |

**보스(선택·스테이지 20 전용)**: `kernel-panic` **커널 패닉** — `grow` + `split2` 복합
(성장하다 죽으면 분열, 분열체도 성장). 최종 시험의 마지막 이벤트 1기.

### abilities 표기·엔진 규칙

- CSV `abilities`는 기존처럼 `;` 구분 조합. 신규 키워드: `grow`, `pair`, `phase`,
  `split2`, `dash`, `resist:printer` (콜론으로 대상 타워 지정 — 확장 가능).
- 모든 주기 파라미터(성장량·은신 주기·대시 주기)는 v0 상수로 코어에 두되, 결정론 검증이
  가능하도록 스폰 시각(`e.spawnedAt`) 기준으로만 계산한다. `love.timer` 금지(기존 규칙).
- `phase` 은신 중에는 타워 자동 타겟팅·스냅샷·투사체 명중 모두 제외(발사된 투사체는
  통과·소멸). 서버라인 도달 판정은 은신과 무관(놓치면 그대로 실점).
- `pair`는 같은 스폰 이벤트의 홀짝 인덱스로 쌍을 맺는다(`e.pairId`). 상대가 죽으면 즉시
  경감 해제. 홀수 마리 스폰 시 마지막 1기는 쌍 없음(경감 없음)으로 스폰.
- `split2` 자식은 부모의 `def`를 공유하되 `splitDepth`를 물려받아 깊이 2에서 중단.
  reachedByType·적 구성 패널 집계는 기존 split 규칙(부모 def 기준)을 따른다.

## 2. 신규 타워 2종 (towers.csv)

| id | 표시명 | 은유 | 메커니즘 (ability) | 학습 포인트 |
|---|---|---|---|---|
| gc-collector | GC 수집기 | Garbage Collector | `splash`: 명중 지점 반경 60px 광역 데미지(중심 100%, 가장자리 50% 선형 감쇠). 저데미지·중속 연사 | 포크 밤·DDoS 물량 대응. "쓰레기는 모아서 치운다" |
| debugger | 디버거 | Breakpoint | `slowfield`: 공격하지 않음. 사거리 내 적 이동 속도 40% 감속(중첩 불가, 최강 1개만 적용) | 레이스 컨디션·초고속 적 대응. "브레이크포인트를 건다" |

- 비용·테크: gc-collector cost 180 `requires=compiler`, debugger cost 80 요구 없음
  (컴파일러 없이도 첫 대응 가능한 보조 타워). limit: debugger는 스테이지당 2
  (감속 도배로 실시간 압박이 죽는 것 방지 — 게임 정체성 보호).
- `slowfield`는 시뮬 결과에 영향을 주므로 코어(`battle.lua`)에서 틱 단위로 결정론적으로
  적용한다(뷰 이펙트 아님). 수치는 전부 towers.csv로.
- 스탯 수치는 전부 잠정치 — 신규 스테이지 solution 회귀(클리어 증명)와 naive 회귀(순진
  배치 패배 증명)를 통과하도록 조정하는 것을 구현 태스크의 완료 조건으로 삼는다.

## 3. 신규 스테이지 13~20 (테마 2+α개, 데이터로만)

기존 12스테이지(코드 영역/데이터 영역/스택/힙 × 3)는 손대지 않는다. 신규 8스테이지의
메모리 영역 테마는 **스레드(13~15) / 프로세스(16~18) / 네트워크(19~20)**.

| # | 신규 적 | 개념(출제 의도) | 비고 |
|---|---|---|---|
| 13 | 메모리 릭 | 나이 비교 타겟팅 (`e.age`) | |
| 14 | 데드락 | 이름별 표적 분산(타워 2기 협동) | |
| 15 | 하이젠버그 | nil 체크·조건 사격 | |
| 16 | 포크 밤 | GC 수집기 도입(광역) | 퍼즐(naive: 단일 고화력 → 분열에 뚫림) |
| 17 | 레이스 컨디션 | 디버거(감속) + 예측 사격 | |
| 18 | 레거시 코드 | 저항 우회 — 테크 체인 재강조 | |
| 19 | DDoS 봇 | 물량전 — 연사·광역 조합 | 30기 러시 이벤트 |
| 20 | 전 종 혼합 + 커널 패닉 | 종합 시험 | 퍼즐(naive 필수 패배) |

- 각 스테이지는 기존 규칙 전부 적용: 12×16 미로(테마와 어울리는 형태 — 스레드=평행
  차선, 프로세스=격리 구획, 네트워크=허브-스포크), `solution_file` 필수(회귀가 클리어
  증명), 타임라인 240s+·공백 ≤40s, `countdown` 15~30s, `theme`/`problem` 칼럼.
- **lore·origin**: Wave A 스키마 그대로 — 신규 적 7종+커널 패닉의 `origin`(이름 유래
  1~2문장: 하이젠베르크 불확정성 원리, 1960년대 다익스트라의 식사하는 철학자, fork bomb
  한 줄 셸 등)과 스테이지 13~20의 lore 8편(briefing+postmortem)을 이 회차에서 집필.
  test_data의 lore 콘텐츠 회귀(Wave A 수정 웨이브에서 추가)가 자동으로 커버한다.

## 4. world API 확장 (api.lua — 최소한만)

- 적 스냅샷에 `age`(스폰 후 경과 초)·`speed`(현재 실효 이동 속도) 추가.
- `world.oldest()` 추가: `age` 최대 적 반환(동률이면 스폰 순). `world.nearest()`와 같은
  스냅샷 규약. 함수 사전 `BUILTIN_DOCS`에 카드 추가(demolish 전례).
- 하이젠버그 은신 중에는 이 API들에서도 보이지 않는다(관측 불가 밈의 일관성).

## 5. 테스트·검증 기준

- 헤드리스: 능력 6종(grow 상한 포함, pair 경감/해제, phase 주기·무적, split2 깊이 제한,
  dash 주기, resist 계수) 각 최소 1건 + world.oldest/age 스냅샷 + 신규 스테이지
  solution/naive 회귀 자동 편입(기존 test_battle 루프가 CSV 순회라 추가 코드 불요).
- 결정론 재현 테스트: 같은 스크립트 2회 실행 → 동일 클리어/패배·동일 serverHP 1건.
- 비주얼(오토플레이 스크린샷 + Read 판독): 신규 적 스프라이트 7+1종(art.lua 코드 생성,
  팔레트 준수), phase 은신 연출(깜빡임), 30기 러시의 진행 바 눈금, GC 스플래시·디버거
  감속 필드 표현, 도감 신규 카드(origin 포함).
- 문서: README(스포일러 없는 수준)·CLAUDE.md(능력 키워드 표·타워 2종·스테이지 규칙) 갱신.
