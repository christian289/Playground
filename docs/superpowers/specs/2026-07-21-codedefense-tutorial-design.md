# Code Defense 튜토리얼 모드 설계서

- 날짜: 2026-07-21 (실시간 코어 루프 개편 반영으로 전면 개정)
- 대상 프로젝트: `love2d-codedefense`
- 전제: 본편 설계서의 4.1/5.1 개정(완전 실시간, 통합 스크립트, build()가 유일한 설치 수단)이
  함께 구현된다. 이 문서의 시나리오는 그 개편 이후의 게임 흐름을 기준으로 한다.
- 상태: 설계 승인됨 (구현 계획 대기)

## 1. 문제

신규 플레이어가 네 지점에서 전부 막힌다: ① 조작법을 모름, ② 목표가 불분명
(서버라인, 적의 출처), ③ 코딩 진입이 당황스러움 (world/self/build가 뭔지 안내 없음),
④ 전반적 온보딩 부재.

## 2. 해법 개요

**단계별 가이드 오버레이.** 별도 모드 없이 스테이지 1~4 위에 말풍선 안내가 뜨고,
해당 칸/요소가 하이라이트되며, 지시된 키만 입력되는 단계진행형. 스테이지마다
완료/스킵이 저장되어 재방문 시 나오지 않는다. 모든 스테이지에 상시 조작 힌트바 유지.

## 3. 플레이어 흐름 (스텝 시나리오 — 실시간 루프 기준)

### 스테이지 1 — 목표와 첫 설치

1. (자유 진행) "버그들이 위에서 내려와요. 바닥의 파란 서버라인에 닿으면 서버가 다쳐요!"
2. (자유 진행, 카운트다운 강조) "카운트다운 동안 첫 타워를 설치할 코드를 준비해요.
   이 게임에서 타워는 오직 코드로만 지을 수 있어요."
3. (버튼만 허용, `built` 이벤트로 진행) "[설치] 버튼을 눌러보세요 — 코드가 자동으로
   타이핑되고 저장되는 걸 지켜보세요" (버튼이 `build("printer", 3, 10, "a")`를
   에디터에 자동 타이핑 + 자동 저장, (3,10) 칸 깜빡임)
4. (버튼만 허용, `built` 이벤트로 진행) "예산이 남았어요. 한 기 더!"
   (두 번째 버튼 → `build("printer", 11, 3, "b")`)
5. (전투 중, `speed_changed` 이벤트 진행) "1/2/4 키로 배속을 조절할 수 있어요"
6. (웨이브 사이 틈, 자유 진행) "적이 잠깐 끊겼어요. 이 틈에 코드를 다듬는 게
   이 게임의 리듬이에요."

앵커/설치 좌표는 회귀 테스트로 클리어가 검증된 배치를 사용한다 (스테이지 1: (3,10), (11,3)).

### 스테이지 2 — 전략 버튼

1. (버튼 유도) "이번 적은 빨라요. [약한 적 우선] 버튼으로 전략 코드를 바꿔보세요"
   (버튼이 on_tick을 교체 타이핑 + 저장)

### 스테이지 3 — 코딩 입문 (직접 타이핑)

1. (자유 진행) "이제 진짜 코드를 만나요! 이번엔 버튼 없이 직접 칩니다."
2. (에디터 입력 허용, 자유 진행) "world는 전장 전체, self는 이 타워예요.
   위 주석의 코드를 그대로 따라 치면 됩니다 — build로 설치, on_tick으로 조종."
3. (자유 진행) "틀려도 괜찮아요 — 저장할 때 문법 오류면 기존 코드가 계속 돌고,
   실행 중 오류는 그 타워만 잠깐 멈출 뿐이에요."
4. (F5 유도, `battle_start`가 아닌 `saved` 이벤트로 진행) "다 쳤으면 F5로 저장 —
   저장하는 순간 전장에 반영돼요!"

### 스테이지 4 — 빈칸과 퀵바

1. (자유 진행) "빈칸(______)만 채우면 돼요"
2. (자유 진행) "F1~F4 퀵바로 코드 조각을 빠르게 넣을 수 있어요"

### 공통 규칙

- **Enter**: 자유 진행 스텝에서 다음으로. **X**: 이 스테이지 튜토리얼 전체 스킵.
- 완료/스킵 시 `progress.tutorial_done[stageId] = true` 저장 → 재방문 시 미표시.
- 리셋 수단은 이번 범위에서 제공하지 않음 (저장 파일 삭제로만 가능).
- 상시 힌트바: play 화면 하단 조작 요약 한 줄 (에디터 키·F5 저장·배속·ESC).
- 튜토리얼 안내가 떠 있어도 게임 시간은 흐른다 (실시간 원칙 유지) — 단, 스테이지 1~2의
  타임라인은 안내를 읽을 여유가 있도록 첫 웨이브를 늦게 설계한다.

## 4. 아키텍처

### 4.1 신규 모듈 `src/tutorial.lua`

`Tutorial(steps)` 위젯 (classic 클래스). 스텝 스키마:

```lua
{
  text = "F5로 저장하면 즉시 설치돼요!",   -- 말풍선 텍스트 (한글)
  anchor = { type = "cell", r = 3, c = 10 } -- 하이라이트 대상 (선택)
         | { type = "ui", id = "editor" }   -- ui id: "editor"|"quickbar"|"serverline"|"budget"|"button"
         | nil,
  allow = { "f5" },                          -- 허용 키 목록 (nil = 전부 허용; 에디터 문자 입력은
                                             --   allow에 "textinput" 토큰이 있으면 통과)
  advance = { on = "key",   key = "f5" }     -- 진행 조건 셋 중 하나:
          | { on = "enter" }                 --   Enter로 넘김
          | { on = "event", event = "built" } -- 게임 이벤트로 넘김
}
```

메서드:

- `:allows(key) → bool` — 현재 스텝의 allow 검사 (X·Enter·ESC는 항상 통과)
- `:allowsText() → bool` — 에디터 문자 입력 허용 여부 ("textinput" 토큰)
- `:keypressed(key)` — Enter 진행, X 스킵, advance.on=="key" 판정
- `:notify(event)` — advance.on=="event" 판정. 이벤트 어휘: `built`(build 성공),
  `saved`(F5 저장 성공), `speed_changed`(배속 변경), `gap`(웨이브 틈 진입)
- `:draw(fonts, gridX, gridY)` — 말풍선(화면 하단 고정 박스) + 앵커 하이라이트
- `:done() → bool` — 전 스텝 완료 또는 스킵됨

### 4.2 스텝 데이터

- `data/curriculum/tutorial_1.lua` ~ `tutorial_4.lua` — 스텝 배열을 반환하는 Lua 파일.
- `data/stages.csv`에 `tutorial_file` 열 추가 (스테이지 5~8은 빈 값).

### 4.3 상태 통합 (최소 침습)

- play 상태의 `keypressed`/`textinput` 최상단에서 allows/allowsText 게이팅,
  이후 `tut:keypressed(key)`.
- 이벤트 지점에서 `tut:notify(...)` (build 성공, 저장 성공, 배속 변경, 웨이브 틈).
- `draw` 마지막에 `tut:draw(...)` (말풍선이 최상위 레이어).
- 스테이지 진입 시 `progress.tutorial_done[stageId]`이면 tut = nil.
- 완료/스킵 시점에 `progress.save`.

### 4.4 저장 스키마 추가

`progress`에 `tutorial_done = { [stageId] = true }`. 기존 파일에 필드가 없으면
`load()`가 빈 테이블로 보강 (기존 세이브 호환).

## 5. 에러 처리·경계

- `tutorial_file`이 빈 값이면 오버레이 없음 (nil 안전).
- 스텝 파일 로드 실패 시 튜토리얼 없이 진행 + 콘솔 경고 — 튜토리얼 데이터가
  게임을 막아서는 안 된다.
- allow 게이팅은 ESC를 막지 않는다.
- X 스킵 즉시 저장.

## 6. 테스트

- `tests/test_tutorial.lua` (신규, suites 등록): allows/allowsText 게이팅,
  key/enter/event 진행, X 스킵 → done, 전 스텝 소진 → done, 깨진 스텝 파일 안전성.
- `db.validate()`에 `tutorial_file` 실재 검사 추가.
- 실시간 개편 쪽 테스트(멱등 build, 저장-재실행, 돈 누적)는 본편 개편 계획에서 다룬다.
- 수동 검증: 새 저장 파일로 스테이지 1~4 실제 플레이.

## 7. 범위 제외

- 튜토리얼 리셋 메뉴, 스테이지 5~8 심화 안내, 입력 검사형 강의, 다국어.
