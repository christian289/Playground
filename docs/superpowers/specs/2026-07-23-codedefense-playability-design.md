# Code Defense 플레이어빌리티 보강 (Wave A) 설계서

2026-07-23. 직접 플레이 + 타워디펜스 장르 비교 분석에서 나온 격차 중, 사용자가 방향을 확정한
소규모 항목들을 한 회차로 묶는다. 신규 타워/적(Wave B), 하드코어 모드(Wave C)는 별도 스펙.

## 사용자 확정 사항 (2026-07-23 문답)

- 일시정지: **도입하지 않는다.** 대신 **슬로우 모드(x0.5)** 를 배속 단계로 추가한다.
  "실시간으로 코드를 치는 압박"이 정체성이므로 시간은 항상 흐른다.
- 타워 철거: **demolish API 전면 도입** (퍼즐 스테이지 포함). 근거: 실시간 타이핑·실시간
  상황 변화가 이 게임의 기본 전제다.
- 성과 등급: **별점 ★1~3 도입** (잔존 HP 기반).
- 확장: 신규 타워·신규 적·완성도·하드코어 모두 진행하되, 이 스펙(Wave A)은 완성도/편의만 다룬다.

## 0. 원칙 (기존 스펙 계승)

- 코어(src/)와 뷰(states/) 분리 유지. 코어 변경은 반드시 헤드리스 테스트 동반.
- 실행 결과 기반 판정. 수치(데미지 등)는 코딩 불가.
- 데이터는 CSV/데이터 파일로. 한글 오류·로그 메시지.
- 모든 스테이지는 결정론 유지 (별점·코칭은 관측일 뿐 시뮬에 영향 없음).

## 1. 슬로우 모드 (뷰 전용)

- `Ctrl+5` → `self.speed = 0.5`. 기존 Ctrl+1/2/4와 같은 위치의 분기에 추가.
- HUD 배속 표기 `x%d` → `x%g` (x0.5 표기). 힌트바 문구 "Ctrl+1/2/4 배속" → "Ctrl+5/1/2/4 배속".
- 튜토리얼 notify("speed_changed") 동일 호출.
- 원시 dt 이펙트(구구 연출, 아바타, ESC 토스트 등)는 이미 배속 무관 — 변경 없음.

## 2. demolish API (코어 + 뷰)

### battle.lua

- `Battle:demolishTower(name)` 추가:
  - 이름으로 타워 검색. 없으면 로그 `[오류] 철거 실패 — "이름" 타워가 없습니다` 후 false.
  - 있으면: towers에서 제거, 점유 해제(occupied), **환불 = floor(cost × 0.5)** 를 money에 가산,
    로그 `[철거] 프린터 → "a" · +50 환불`, true 반환.
  - 크래시/비활성 타워도 철거 가능. 구구 클래스도 철거 가능(재소환 시 limit 검사는 현존
    개수 기준이므로 자연스럽게 다시 1개 허용 — 스테이지당 1개 동시 존재 규칙으로 해석).
- setScript 멱등성과의 상호작용: build는 이름 기준 멱등이므로, 스크립트에 build("printer",r,c,"a")가
  남아 있는 채 demolish("a")를 on_tick에서 호출하면 다음 저장 때 재건설된다. 이는 버그가 아니라
  실시간 규칙의 결과다 — 함수 사전 demolish 항목에 이 함정을 명시한다.

### api.lua

- `env.demolish = function(name) return battle:demolishTower(name) end` — build와 동일하게
  카운트다운 중에도, on_tick 안에서도 호출 가능.
- 아이템 게이팅 없음 (기본 API). BUILTIN_DOCS에 demolish 카드 추가(시그니처·환불 50%·재건설 함정).

### 테스트 (tests/)

- build→demolish: 타워 수 감소, 환불 금액 정확, 칸 재사용 가능(같은 자리 build 성공).
- 미존재 이름: false + 한글 오류 로그.
- on_tick 내부 demolish: 다음 틱 반영, 크래시 없음.
- demolish 후 같은 이름 build → 새 타워(멱등 캐시가 남아 재설치를 막지 않는지).
- 기존 206+2 스위트 전체 통과 유지.

## 3. 별점 ★1~3 (뷰 전용 — 저장 필드 추가 없음)

- 산식(고정): 클리어 시 잔존 HP 기준 — `HP ≥ 8 → ★3`, `HP ≥ 4 → ★2`, `그 외 클리어 → ★1`.
  기존 저장값 `records[id].bestHP`로 계산하므로 세이브 마이그레이션 불필요.
- 스테이지 선택: 행 기록 텍스트를 `[★★☆ · HP 5 · 구]` 형태로. ★/☆ 글리프가 NanumGothic에
  없으면(전례: ✓, 九) 대체 문자('*' 또는 색상 원)로 — 구현 시 글리프 렌더 확인 필수.
- 결과 화면(클리어): 이번 판 별(이번 HP 기준)과 최고 기록 별을 함께 표시.
  `★★ 달성 (최고 ★★★)` 식 한 줄.
- 튜토리얼/README 문구 갱신은 이 회차 문서 태스크에 포함.

## 4. 위기 경고 (뷰 전용)

- 조건: `battle.serverHP ≤ 3` 이고 status == "running".
- 연출: 전장 가장자리 붉은 비네트(사각 테두리 그라데이션, 알파 0.25 사인 펄스 주기 1.2초 —
  원시 dt) + 상단 HUD의 "서버 HP n" 숫자를 빨간색으로.
- redFlash(피격 순간 플래시)와 별개, 동시 표시 가능.

## 5. 웨이브 예고 색상 (뷰 전용)

- 진행 바 스폰 눈금(현재 흰 단색 1px)을 해당 이벤트 적 종류의 `enemies.csv color`로 칠한다.
- 이미 지나간 눈금은 알파 0.35로 감쇠. 크기·위치 불변.

## 6. 통계 프로필 (도감 4번째 탭, 뷰 전용)

- codex 탭 [타워]/[몬스터]/[내 함수] 뒤에 [프로필] 추가.
- 내용(전부 기존 저장 데이터 파생): 총 배포(모든 records.tries 합) / 총 클리어 스테이지 수 /
  별 합계(3절 산식) / 등록 함수 수(funcbook) / 구구 클래스 발견 여부(??? 또는 발견) /
  스테이지별 한 줄: `1. 첫 타워 — 시도 3 · ★★★`.
- 목록이 길면 기존 도감 스크롤 패턴 재사용.

## 7. 패배 코칭 (코어 소폭 + 뷰)

- battle에 `reachedByType[enemyId] = n` 카운터 추가 (적이 서버라인 도달 시 증가).
  순수 데이터 수집 — 시뮬 로직 영향 없음. 헤드리스 테스트 1건(도달 수 집계 정확성).
- 패배 화면에 한 줄 추가: `가장 많이 도달: 널 포인터 7기 — 사거리와 화력 배치를 다시 보라`.
  (문구는 최다 도달 종 1개만, 동률이면 먼저 스폰된 종.)
- 이미 표시 중인 "버틴 시간 N초 / 300초" 아래 배치.

## 비범위 (다음 스펙)

- Wave B: 신규 공격 타워(스플래시/감속 — 새 개념 커리큘럼과 결합), 신규 적(포크밤 분열 강화,
  하이젠버그 은신, 메모리릭 성장), 스테이지 밸런스 재조정.
- Wave C: 하드코어 모드(50단계 코드 고정 커리큘럼, 클리어 타임 SNS 인증).
- 스테이지 선택/도감 마우스 일관성(기존 defer 목록 유지).

## 테스트·검증 기준

- 헤드리스: demolish 4건 + reachedByType 1건 신규, 기존 스위트 전체 통과.
- 비주얼: 슬로우 HUD 표기, 별점(선택/결과), 비네트, 눈금 색상, 프로필 탭, 코칭 줄 —
  오토플레이 하네스 스크린샷으로 확인(스크래치패드 저장·Read 판독 필수).
- 데이터 주도 회귀(전 스테이지 솔루션 클리어) 유지 — demolish는 솔루션에 등장하지 않으므로
  기존 회귀에 영향 없음.
