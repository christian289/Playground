# Code Defense 스테이지 경험 개선 설계서

- 날짜: 2026-07-22
- 대상: `love2d-codedefense` (feature/codedefense-tutorial 브랜치 위에 얹음)
- 배경: 사용자 실플레이 피드백 — "무엇이 얼마나 나오는지 안 보이고, 300초 중 대부분이
  빈 시간이라 언제 끝나는지 모르겠다" + 도감·히든 타워·코딩테스트 감성·메모리 테마 요청.
- 상태: 설계 승인됨

## 0. 판정 철학 (명문화)

플레이어 코드는 답안지와 비교되지 않는다. Lua 샌드박스에서 **실제로 실행**되며,
해결 방식·변수명·스타일과 무관하게 **실행 결과가 같으면 동일하게 동작**한다.
거부되는 것은 문법 오류뿐이고, 클리어 판정은 코드가 아니라 결과(300초 생존)다.
`curriculum/*_solution.lua`는 회귀 테스트 전용, `*_hints.lua`는 에디터 초기 텍스트일 뿐이다.
이 원칙은 향후 다른 언어 진영(외부 프로세스 어댑터)에도 동일하게 적용한다.

## 1. 적 구성·진행 UI (전장 오버레이, 뷰 전용)

- **적 구성 패널** (전장 우상단, 반투명 박스 — 좌하단 로그 오버레이와 대칭):
  이 스테이지 타임라인에 등장하는 **적 종류별 미니 스프라이트 + "처치 n / 전체 N"**.
  전체 수는 타임라인에서 계산(결정론이라 정확), 카운트다운 중에는 예정 수 전체 표시,
  전투 중 처치 수 실시간 갱신. 처치 수 = 전체 − (미스폰 + 필드 생존 + 서버라인 도달).
- **진행 바** (상단 HUD 아래 얇은 바): 300초 대비 현재 시각 + **스폰 이벤트 시점 눈금**.
  모든 스폰이 끝나면 "잔여 적 소탕 + 생존" 안내 텍스트.
- 구현: battle의 timeline/spawned/clock **읽기 전용**. `Battle.TOTAL`(=300) 상수만 노출
  (로직 무변경). 기존 테스트 무손상.

## 2. 300초 꽉 찬 타임라인

- 8개 스테이지 타임라인 재설계: **스폰이 초반부터 약 280초까지 이어지고, 무스폰 공백은
  최대 25초**(숨 고르기 용도). 후반으로 갈수록 밀도 상승. 스테이지 1은 튜토리얼 안내를
  읽을 초반 여유 유지.
- **validate() 규칙 추가 (전 스테이지 데이터 강제)**:
  - 마지막 스폰 이벤트 종료 시각 ≥ 240초
  - 인접 스폰 이벤트 간 공백 ≤ 40초 (이벤트 지속시간 = at + (count−1)×interval 고려)
- 리밸런싱 후 8개 정답 회귀 전부 재클리어 확인 (결정론 유지).

## 3. 도감 (타이틀 메뉴 4번째 항목 "도감")

- **타워 탭**: 타워별 카드 — 스프라이트 + 이름 + 역할 설명 + 스탯 표
  (비용/데미지/사거리/쿨다운/요구 테크) + `build("printer", 3, 10, "a")` 예시 코드.
  towers.csv에서 읽으므로 밸런스 변경 시 자동 반영.
- **몬스터 탭**: 몬스터별 카드 — 스프라이트 + 실제 IT 의미 + 게임 내 능력 (enemies.csv).
- 조작: ←/→ 탭 전환, ↑↓ 항목 이동, ESC 타이틀로.
- 히든 타워(§4)는 발견 전 "???" 실루엣 카드 + 수수께끼 힌트만 표시.

## 4. 히든 타워 "구구 클래스" (한국 코딩 밈 오마주)

- **소환**: `build("gugu-class", r, c, name)` — 한글 별칭 `"구구클래스"`도 인정.
- **히든 연출**: 도감 "???" 카드의 수수께끼 —
  "장애가 터지면 회의실 화면 앞에서 실시간으로 코딩을 시작한다는 전설의 클래스.
  Java로 짠 그것의 이름을 아는 자만이 소환할 수 있다."
  최초 설치 성공 시 카드 공개 + `progress.gugu_found = true` 영구 저장.
- **메커니즘 — 단(段) 성장**: 설치 시 2단 시작, 전투 중 30초마다 +1단 (최대 9단).
  실효 데미지 = 기본 데미지 × 현재 단 (기본 6 → 9단 54). 단 상승 시 전투 로그:
  "[구구 클래스] N단 돌입! N × 1 = N..."
- **제한**: 스테이지당 1개 — 초과 설치 시 한글 오류 "구구 클래스는 스테이지당 하나뿐입니다".
- **데이터 주도**: towers.csv에 `limit`(스테이지당 개수, 빈 값=무제한), `hidden`(1=도감 ???),
  `ability`(엔진 능력 키워드 — `gugu`) 열 추가. battle.lua에 limit 검사 + gugu 능력
  (단 타이머·배율·로그) 구현, 헤드리스 테스트로 검증 (제한/성장/배율/별칭/도감 공개 플래그).
- 스탯 초안: cost 120, damage 6, range 150, cooldown 1.0, requires 없음 (밸런스는 구현 시 조정).

## 5. 코딩테스트 문제 브리핑

- 스테이지 진입 카운트다운 동안 전장 중앙에 **문제 카드** 오버레이 (코딩테스트 문제지 형식):

  ```
  [문제 3] 따라 치기            메모리 영역: 스택
  새벽 배포 직후 버그가 유입되고 있다. 300초 동안 서버라인을 사수하라.
  제한: 예산 220 · 유입 예정 32기        제출: F5 · 채점: 300초 생존
  ```

- 적 총수는 타임라인에서 계산. Enter로 닫기, 전투 중 **I 키**로 재열람.
- 데이터: stages.csv에 `theme`(메모리 영역명), `problem`(한 줄 문제 서술) 열 추가.
- 튜토리얼 오버레이와 겹칠 때는 튜토리얼이 우선 (문제 카드는 그 아래 z순서).

## 6. 메모리 영역 테마 미로

| 스테이지 | 영역 | 미로 형태 |
|---------|------|----------|
| 1~2 | 코드 영역 | 명령어처럼 정연하게 줄지은 가로 행 통로 |
| 3~4 | 데이터 영역 | 고정 크기 블록이 격자로 배치된 정적 구조 |
| 5~6 | 스택 | 위에서부터 층층이 쌓이는 지그재그 (내려갈수록 좁아짐) |
| 7~8 | 힙 | 단편화된 불규칙 조각들 사이로 흐르는 통로 |

- 8개 미로 재설계 (12×16 규격, 건설칸 ≥ 6, 스폰 열·도달 가능성은 기존 validate가 보장).
- 테마명은 문제 브리핑 카드에 표기 (§5). 타일 틴트 변주는 범위 제외 (YAGNI).
- 미로가 바뀌므로 정답 build 좌표 재검증 — 회귀 테스트가 강제.

## 6.5 퍼즐형 레벨 디자인 (코딩테스트 암시 강화 — 전부 데이터 주도)

- 스테이지 4·6·8을 **퍼즐 스테이지**로 지정: 미로·예산·적 구성이 "의도된 배치"를 강제한다.
  - 4 (데이터 영역): 적 경로에 사거리가 닿는 건설칸이 사실상 2곳뿐 — 오배치 시 총알이 닿지 않음
  - 6 (스택): null-ptr 러시 밀도가 프린터 화력을 초과 — 특정 위치 컴파일러+스나이퍼 필수
  - 8 (힙): 커버리지가 갈라진 단편화 구조 — 분할 지점 3곳 배치 필수
- **데이터 스키마**: stages.csv에 `puzzle`(1=퍼즐, 빈 값=자유) 및 `naive_file`
  (순진 배치 스크립트 경로 — 예: `curriculum/004_naive.lua`) 열 추가.
- **검증(데이터 주도 회귀)**: 회귀 루프가 CSV를 읽어 — `solution_file`은 clear,
  `naive_file`이 있으면 그 스크립트는 **defeat**임을 결정론으로 증명.
  ("브루트포스는 시간초과" 감각을 데이터로 보장. 코드 판정 철학 §0은 불변 —
  좁아지는 것은 전술 해공간이지 코드 형태가 아니다.)
- 비퍼즐 스테이지(1~3·5·7)는 자유 배치 유지.

## 6.6 구구 클래스 소환 연출 (뷰 전용)

- 뷰(play)가 gugu-class 타워 등장을 frame-diff로 감지 → **1.2초 전체 화면 연출**:
  흰 플래시 → 금색 테두리 펄스 + 전장 셰이크 + 중앙 배너 "전설의 클래스, 소환." +
  구구단 텍스트 파티클("2 × 1 = 2" 등)이 떠오름. 코어 무변경.

## 6.7 배포 로그 (스테이지 기록 — 히든 사용 여부 포함)

- 개발자 친숙한 "배포 이력" 콘셉트.
- **저장** `progress.records[stageId]` = `{ tries, clears, bestHP, lastResult, gugu }`
  (gugu = 한 번이라도 구구 클래스 투입 시 true 영구).
- **result 화면**: 이번 판 로그 한 줄 — 성공: "배포 #N 성공 · 서버 HP h 잔존 · 타워 t기
  [· 구구 클래스 투입 ✓]" / 실패: "배포 #N 롤백 · ...".
- **stageselect**: 스테이지 항목 옆 기록 표기 — 예: `[클리어 · HP 9 · 九]`
  (九 = 구구 사용 마크). 기록 없으면 미표기.

## 7. 테스트·검증

- 신규 헤드리스: gugu 능력(단 성장·배율·30초 타이밍·로그), limit 검사, 한글 별칭,
  progress.gugu_found 왕복, validate 새 규칙(양성+음성 픽스처), 적 총수 계산 유틸.
- 기존 156개 무손상 + 8개 스테이지 회귀 재클리어.
- 스크린샷 검증: 적 구성 패널·진행 바·문제 카드·도감(타워/몬스터/??? 카드)·새 미로 8종.

## 8. 범위 제외

- 타워 업그레이드 시스템(도감은 현 스탯만), 스테이지별 타일 틴트, 도감 코드 예제 실행,
  다른 언어 진영 어댑터(v2), 구구 클래스 전용 스프라이트 외 추가 이펙트.
