# Code Defense — 코딩 교육용 타워디펜스 설계서

- 날짜: 2026-07-21
- 프로젝트 폴더(예정): `love2d-codedefense`
- 엔진: LÖVE 11.5 (데스크톱 우선)
- 상태: 설계 확정 대기 (사용자 리뷰 전)

## 1. 개요

IT 세계관 타워디펜스이자 코딩 교육 게임. 플레이어는 서버실을 지키는 개발자로,
타워의 두뇌를 **직접 작성한 Lua 코드**로 채운다. "버그", "널 포인터", "DDoS 봇넷" 같은
IT 위협(밈 몬스터)이 화면 위에서 소나기처럼 쏟아져 내려오고, 코드가 조종하는 타워가
바닥의 서버라인에 닿기 전에 지워낸다 — 한컴타자연습 "소나기"의 감각을
"타이핑으로 단어를 지운다"에서 "코드로 몬스터를 지운다"로 계승한다.

IT 용어·밈은 아이템/장비로 등장하며, 장착하면 **새 API가 코드에서 해금**된다.
게임을 하다 보면 IT 용어의 실제 의미를 자연스럽게 배우게 되는 것이 목표다.

## 2. 교육 철학 (설계 전반을 지배하는 원칙)

1. **반복 타이핑이 곧 학습이다.** 코드 패턴을 손으로 반복해서 치게 만드는 구조가 최우선이다.
2. **스테이지는 완전히 정적(결정론적)이다.** 적 구성·출현 시각·미로 배치에 랜덤성이 없다.
   외워서 타이핑하는 것은 편법이 아니라 **이 게임이 목표하는 반복 숙달의 궁극적 형태**다.
   (부수 효과: 클리어 타임 스피드런의 공정성이 자동으로 확보된다.)
3. **커리큘럼이 게임 메커니즘이다.** 배우는 개념(데이터 타입, 이벤트, 스레드 등)이
   장식이 아니라 실제 게임 규칙·파워로 작동한다.
4. **수치는 직접 대입할 수 없지만, 코드 솜씨가 실효 성능을 만든다.** `self.damage = 9999` 같은
   직접 대입은 불가능하다 — 기본 수치는 타워 종류 + 아이템이 결정한다. 대신 코드를 **어떻게**
   짰느냐에 따라 발사 속도·총알 크기 같은 실효 성능이 달라진다 (5.6 코드 크래프트 참조).
   같은 타워를 가져도 기계적으로 똑같이 동작하지 않는다.
5. **언어에 우열은 없다.** 언어 진영은 에이지 오브 엠파이어의 문명처럼 **컨셉이 다를 뿐**,
   "좋은 언어 / 성능 좋은 언어"로 묘사하지 않는다. 밸런스 목표는 전 진영 동일하다.
6. **장애는 격리된다.** 한 타워의 코드가 죽어도 다른 타워는 동작한다.
   에러 처리 자체가 교육 소재다 (크래시, 워치독, 타임아웃).

## 3. 모드 구조

### 3.1 일반 모드 — 300단계 누적 성장 캠페인

아이템 인벤토리, 공용 함수 라이브러리, 밈 도감, 스니펫 퀵바가 전부 **영구 누적**된다.

| 구간 | 조작 방식 | 배우는 것 |
|------|----------|----------|
| 1~10 | **버튼만.** 타겟 우선순위를 드롭다운으로 선택. 누를 때마다 "이 버튼은 사실 이 코드입니다" 미리보기 표시 | 코딩 공포 제거, 다음 구간 예고 |
| 11~20 | **빈칸 채우기 타이핑.** 함수 뼈대 + placeholder 힌트, 예제 코드를 보고 그대로 따라 치면 통과 | 코드 치는 손, 문법 형태에 대한 눈 |
| 21~100 | **직접 코딩, 기초 문법.** 스테이지마다 개념 하나: 변수 → 데이터 타입 → 조건문 → 반복문 → 함수 → 테이블 | 기초 문법 전체 |
| 101~300 | **고급 개념 = 사기급 능력.** 이벤트 핸들러(`on_spawn`/`on_kill`/`on_wave_start`), 타이머/틱 훅, 코루틴(비동기), 멀티스레딩 | 우아한 프로그래밍 패턴 — 훅/이벤트는 실제로 압도적으로 강하게 설계해 "왜 우아한가"를 파워로 체감 |

### 3.2 하드코어 모드 — 50단계 지식 검증 + 스피드런

- 일반 모드 30단계 클리어 시 해금.
- **아이템 전부 사용 불가, 라이브러리·퀵바 초기화(빈 에디터), 기본 API만.**
  머리와 손에 남은 지식으로만 승부한다.
- **시간 구조**: 5분 고정이 아니다. **일정 시간마다 웨이브가 무조건 밀려온다** —
  이전 웨이브를 못 잡았어도 시계가 되면 다음 웨이브가 겹쳐 내려온다.
- **코딩 타이밍**: 타이머가 멈추는 준비 단계가 없다. **전투 중 실시간으로 에디터를 열고
  코드를 고쳐야 한다.** (인간 타이핑의 한계 → v2 AI 에이전트 서사의 출발점)
- **클리어 조건**: 스테이지별 정해진 웨이브 수를 전부 소화하고 생존.

### 3.3 하드코어 특전 (1회성)

- 하드코어 스테이지 **최초 클리어**마다 특전 토큰 1개 (재클리어로는 획득 불가).
- 일반 모드에서 소모형으로 사용: 시작 예산 2배 / 웨이브 하나 건너뛰기 / 크래시 타워 즉시 부활 등.
- 저장 데이터: `hardcore_cleared` 목록, `perk_tokens` 수량.

### 3.4 하드코어 클리어 타임 인증·공유

- 스테이지별 클리어 타임 기록 (개인 최고 기록 갱신 표시), 결과 화면은 스피드런 스타일:
  클리어 타임, 웨이브별 랩타임, 코드 줄 수, 타워 수.
- [공유] 버튼: ① 인증 카드 PNG 자동 생성·저장 (게임 캡처 + 기록 오버레이, SNS 첨부용 비율),
  ② 해시태그 포함 공유 텍스트 클립보드 복사 (`love.system.setClipboardText`),
  ③ 게시 URL 스킴으로 브라우저 열기 (X 등).
- 저장 데이터에 리플레이 시드·검증 해시를 미리 포함 → v2 온라인 리더보드 서버 검증에 사용.
- "클릭하면 열리는 기록 링크"(고유 URL)는 웹 서버가 필요하므로 **v2 예약**.

### 3.5 언어 진영 시스템

에이지 오브 엠파이어의 문명처럼, **언어 = 진영**이다. 발전의 큰 흐름은 모든 진영이 비슷하되
컨셉만 다르다. 우열 묘사 금지 (철학 5).

| 진영 | 실제 언어의 성격 | 게임 컨셉 (예시, 밸런스는 구현 시 조정) |
|------|-----------------|----------------------------------------|
| Lua | 경량, 어디에나 임베딩 | 타워 설치 비용↓, 설치 가능 칸 제약 완화 |
| Python | 간결, 배터리 포함 | 짧은 코드 보너스, 표준 라이브러리 일부 아이템이 기본 제공 |
| JavaScript | 이벤트 루프, 비동기 | 이벤트/콜백 API 조기 해금, 훅 계열 강화 |
| C# | 정적 타입, 견고함 | 타입 매칭 보너스, 시작 전 강력한 정적 진단(문법·타입 오류 상세 안내) |

- **하드코어 모드**: 시작 시 **주력 언어 진영을 선택**하고 50단계를 그 진영으로 쭉 진행한다.
  랭킹은 **언어별 타임어택 보드로 분리** — "Python 진영 12단계 1위" 같은 인증이 가능하다.
- **일반 모드**: **모든 스테이지에서 언어를 1개 이상 선택**할 수 있다. 복수 선택 시
  타워마다 언어를 배정하는 혼성 운용이 가능하다 (폴리글랏 플레이).
- **v1 범위**: 진영 프레임워크(선택 UI, 진영 보너스 데이터, 언어별 랭킹 분리 저장)는 v1에 넣되,
  실행 가능한 진영은 **Lua 하나로 시작**한다. Python/JS/C#은 v2에서 외부 프로세스 어댑터로
  추가한다 — 프레임워크가 미리 있으므로 어댑터만 붙이면 된다.

## 4. 코어 루프와 전투 규칙

### 4.1 일반 모드 한 판 (5분 고정)

1. **준비 단계** (시간 무제한, 타이머 정지) — 예산으로 타워 배치/업그레이드,
   아이템 장착, 에디터에서 스크립트 작성·수정.
2. **웨이브 자동 전투** — [시작]을 누르면 적이 내려오고 코드가 타워를 조종.
   플레이어는 관전만 (1x/2x/4x 배속). 크래시 타워, 킬 로그, 함수 호출이 실시간 표시.
3. 스테이지 데이터의 `pause_at` 시점마다 타이머 정지 → 준비 단계 재진입.
4. **전투 시간 총 300초(5분) 생존 = 클리어.** 준비 시간은 5분에 포함되지 않는다.

### 4.2 맵

- **모든 스테이지가 동일한 고정 크기 그리드** — 가로 12 × 세로 16칸 (v1 확정값).
- 적은 **위에서 아래로** 미로 벽을 따라 내려온다 (낙하형 + 미로 결합).
- 난이도 조절 수단은 **미로 배치와 몬스터 구성뿐**이다. 맵 크기·규칙은 불변.
- 바닥의 서버라인에 적이 닿으면 서버 HP 감소, 0이 되면 패배.

### 4.3 테크 의존성 (타워 테크트리)

스타크래프트의 시설 의존, 워크래프트3 뱀파이어 디펜스류 유즈맵처럼 **특정 타워를 보유해야만
열리는 건설·업그레이드**가 있다. 예시 (밸런스는 구현 시 조정):

- "컴파일러" 타워 보유 → 모든 타워의 티어2 업그레이드 해금
- "패키지 매니저" 타워 보유 → 타워당 아이템 장착 슬롯 +1
- "CI 서버" 타워 보유 → 크래시한 타워의 워치독 재시작 시간 단축
- 티어3 타워는 해당 계열 티어2 타워가 필드에 존재해야 건설 가능

테크 타워 자체는 공격력이 없거나 약한 대신 전략적 가치를 가진다 — 지킬 가치가 있는 건물이
생기면서 미로 설계와 타워 배치에 깊이가 생긴다. 정의는 `towers.csv`의 `requires` 열로
선언한다 (예: `requires` 셀에 `compiler`).

## 5. 코딩 시스템

### 5.1 타워 스크립트

- 타워마다 `on_tick(self, world)` 함수 하나. 전투 중 초당 10회 호출되는 의사결정 함수.
- 최소 코드 한 줄로 시작 가능: `self:attack(world.nearest())`
- **공용 라이브러리 탭**: 여러 타워가 공유하는 함수 모음. `require` 없이 자동 로드.
  "코드 재사용" 개념이 UI 구조로 체화된다.
- 1~10구간의 버튼 UI는 내부적으로 같은 코드 한 줄을 생성한다 — 실행 시스템은 하나다.

### 5.2 Lua 샌드박스

- `setfenv`(LuaJIT/Lua 5.1)로 화이트리스트 환경 격리: `io`/`os`/`love` 접근 불가,
  `math`/`table`/`string` + 게임 API만 노출.
- `debug.sethook` count 훅으로 **틱당 명령 수 예산** 강제. 무한 루프 → 타워 "타임아웃" 상태로 수 초 정지.
- CPU 예산도 게임 소재: 아이템 "CPU 코어 증설" = 명령 예산 증가.

### 5.3 에러 처리 = 교육 기회

- 문법 오류: 준비 단계에서 [시작] 버튼이 막히고 에디터에 줄 번호 + 한글 설명.
- 런타임 오류: 해당 타워만 "크래시" 상태(연기 이펙트) 3초 → 자동 재시작(워치독).
  오류 로그가 전투 화면에 흐른다. 다른 타워는 계속 동작 — 장애 격리를 눈으로 배운다.

### 5.4 에디터

- 게임 내장: 모노스페이스 + 나눔고딕(한글 주석 지원), 줄 번호, 기본 문법 하이라이트,
  placeholder 힌트(11~20구간). v1은 자동완성/멀티커서 없음.

### 5.5 스니펫 퀵바 (일반 모드 전용)

- 에디터 하단 버튼 슬롯 8~10칸. 누르면 커서 위치에 즉시 삽입. **F1~F10 단축키** 지원.
- 등록 단위: 키워드(`if ... then ... end`) / 함수 템플릿(뼈대 + 커서가 첫 빈칸으로 점프) /
  내 라이브러리 함수 호출.
- 구간별 기본 프리셋 자동 채움 (`data/curriculum/`), 플레이어가 자유 교체, 진행도에 저장.
- **하드코어 모드에서는 비활성** — 일반 = 도구 활용 생산성, 하드코어 = 몸에 익은 지식.

### 5.6 코드 크래프트 — 코드 솜씨가 실효 성능을 바꾼다 (철학 4의 구현)

같은 타워라도 코드에 따라 전혀 다르게 싸운다. 직접 수치 대입 없이, 코드의 **효율과 전략**이
성능으로 번역되는 두 축:

- **오버클럭 (틱 효율 → 발사 속도)**: 틱마다 명령 예산이 주어지는데, 판단을 예산보다 일찍
  끝내면 남은 예산이 오버클럭 게이지로 전환되어 **발사 속도가 올라간다**. 낭비가 많은 코드
  (매 틱 전체 적 리스트 재정렬 등)는 예산을 소진해 공속이 낮고, 캐시·조기 반환으로 다듬은
  코드는 같은 타워로 더 빠르게 쏜다. 최적화가 눈에 보이는 보상이 된다.
- **차지샷 (전략 → 총알 크기)**: `attack`을 아끼면 차지가 누적되어 총알이 커지고 관통이
  붙는다. 언제 모으고 언제 방출할지를 코드가 결정한다 — "지금 쏠까, 모을까"라는 판단 로직
  자체가 화력 곡선을 만든다.

두 축 모두 읽기 전용 상태(`self.charge`, `self.overclock`)로 노출되어 코드가 참조할 수 있다.

## 6. IT 밈 시스템

### 6.1 아이템 = API 해금

전부 CSV 데이터로 정의 — 새 밈 추가 = CSV 행 하나 추가 (7.2 참조). 초기 풀:

| 아이템 | 실제 IT 의미 | 해금 API / 효과 |
|--------|-------------|-----------------|
| 캐시 | 결과 저장으로 재계산 회피 | `cache.get/set` — 적 분석 스킵, 공속 상승 |
| 스레드풀 | 작업 병렬 처리 | `threads.attack(...)` — 동시 다중 타겟 |
| 로드밸런서 | 부하 분산 | `lb.assign(tower, enemy)` — 어그로 분배 |
| 크론탭 | 예약 작업 | `cron.every(sec, fn)` — 주기 자동 실행 |
| 웹훅 | 이벤트 알림 | `on_spawn(fn)` — 적 등장 즉시 반응 |
| 가비지 컬렉터 | 메모리 정리 | 필드 잔해/디버프 주기 제거 |
| 프로파일러 | 성능 분석 | 적 상세 정보(약점 타입, 경로 예측) 조회 |
| CPU 코어 증설 | 연산 자원 | 틱당 명령 예산 증가 |

### 6.2 적도 밈이다

버그(기본), 널 포인터(맞은 타워를 크래시시킴), 오프-바이-원(경로를 한 칸 벗어남),
스파게티 코드(궤적 꼬임), 기술 부채(방치할수록 커지고 강해짐), DDoS 봇넷(대량 물량),
좀비 프로세스(죽어도 부활), 힙 오버플로우(보스).

**예외 몬스터 계열 (진영별 세트)**: 예외(Exception)는 언어마다 생김새가 달라서, 예외 몬스터는
**언어 진영별 세트**로 등장한다. v1의 Lua 세트 — Lua에는 .NET 같은 타입화된 예외 계층이 없고
런타임이 뱉는 정형화된 오류 메시지가 있을 뿐인데, 그 메시지가 그대로 몬스터 이름이 된다:

| 몬스터 (실제 Lua 오류 메시지) | 의미 | 게임 컨셉 (예시) |
|------|------|------|
| `attempt to index a nil value` | nil의 필드에 접근 | 널 포인터의 Lua 사촌 — 맞은 타워의 다음 판단 1회를 nil로 만듦 |
| `attempt to call a nil value` | 없는 함수를 호출 | 타워 하나의 `on_tick` 호출을 잠시 무효화 |
| `attempt to perform arithmetic on a nil value` | nil과 산술 연산 | 접촉한 타워의 오버클럭 게이지를 0으로 |
| `attempt to concatenate a nil value` | nil 문자열 연결 | 분열해서 여러 마리가 됨 (`..`처럼 이어붙음) |
| `bad argument #1 to 'attack'` | 함수 인자 타입 오류 | 타워의 다음 공격이 빗나감 |
| `stack overflow` | 재귀 폭주 | 죽을 때마다 한 단계 작은 자신을 남김 (재귀) |
| `cannot resume dead coroutine` | 끝난 코루틴 재개 시도 | 좀비 프로세스의 강화판 — 부활하지만 점점 느려짐 |

도감에는 각 몬스터가 "실제로 이 오류가 언제 나는지 + 어떻게 고치는지(pcall, nil 체크)"를
기록한다. v2에서 진영이 추가되면 C# 세트(`NullReferenceException`, `InvalidOperationException`,
`ArgumentNullException`…), Python 세트(`TypeError`, `KeyError`, `IndexError`…),
JS 세트(`TypeError`, `ReferenceError`, `RangeError`…)가 같은 형식으로 들어온다 —
플레이어는 몬스터를 잡으며 언어별 예외 체계의 차이를 자연스럽게 비교하게 된다.

### 6.3 밈 도감 (영구 수집)

획득 용어마다 ① 실제 IT 의미, ② 게임 내 효과, ③ 활용 예제 코드 한 토막.
"이 게임 하다가 용어 배웠다"는 리뷰가 목표. 신규 밈은 CSV 행 추가로 계속 공급.

### 6.4 커리큘럼-메커니즘 매핑 예시

- 데이터 타입 챕터: 적에게 타입이 있고 타입이 맞는 공격만 유효 (`string` 적 ↔ `string` 탄환).
- 이벤트 챕터: `on_spawn`/`on_kill` 핸들러 API가 열리며 반응 속도가 폴링과 비교 불가로 빨라진다.

## 7. 아키텍처

### 7.1 폴더 구조

```
love2d-codedefense/
├─ main.lua / conf.lua
├─ src/
│  ├─ sandbox.lua      ← Lua 샌드박스 (제한 env, 명령 예산, 타임아웃)
│  ├─ api.lua          ← 타워 스크립트에 노출되는 게임 API (아이템이 항목 추가)
│  ├─ editor.lua       ← 게임 내 코드 에디터 (커서, 줄번호, 하이라이트, placeholder, 퀵바)
│  ├─ tower.lua / enemy.lua / projectile.lua
│  ├─ grid.lua         ← 고정 크기 그리드 + 미로 벽 + 위→아래 경로 탐색
│  ├─ waves.lua        ← 전투 타임라인 실행기 (일반: 5분+pause_at / 하드코어: 주기 강제 웨이브)
│  ├─ csv.lua          ← 경량 CSV 파서 (따옴표 필드, 셀 내 리스트 `;` 구분 지원)
│  └─ progress.lua     ← 저장/로드 (진행도, 도감, 라이브러리, 인벤토리, 퀵바, 특전, 기록)
├─ states/             ← title / stageselect / prep / battle / result / codex
├─ data/
│  ├─ items.csv        ← 밈 아이템 (1행 = 아이템 1개)
│  ├─ enemies.csv      ← 밈 몬스터 + 예외 몬스터 (1행 = 몬스터 1개)
│  ├─ towers.csv       ← 타워 정의 (requires 열이 4.3 테크 의존성 선언)
│  ├─ codex.csv        ← 도감 텍스트 (용어, 실제 IT 의미, 게임 효과, 예제 코드 파일 참조)
│  ├─ stages.csv       ← 스테이지 메타 (1행 = 스테이지 1개, 300+50행으로 확장)
│  ├─ timelines.csv    ← 적 출현 스케줄 (1행 = 스폰 이벤트 1개, stage_id로 연결)
│  ├─ mazes/           ← 미로 배치 텍스트 파일 (12x16 문자 맵, 1스테이지 1파일)
│  └─ curriculum/      ← 튜토리얼·placeholder 템플릿·정답 코드 (코드 조각이라 Lua 파일 유지)
└─ lib/                ← classic, hump (기존 프로젝트와 동일 패턴)
```

### 7.2 게임 데이터는 전부 CSV로 관리한다 (300개 확장의 핵심 — 스테이지는 코드가 아니라 데이터)

표 형태 데이터는 전부 CSV다. 엑셀/구글시트에서 편집·밸런싱하고, 커뮤니티 밈 제안도 CSV 행
하나로 받는다. 셀 안의 리스트는 `;` 구분, 다중 행 텍스트(미로 맵, 예제 코드, placeholder
템플릿)는 CSV에 넣지 않고 **파일 경로를 참조**한다. 로드는 자체 `src/csv.lua` 파서.

`stages.csv` — 1행 = 스테이지 1개:

```csv
id,mode,concept,maze_file,budget,languages,pause_at,wave_clock,hints_file,solution_file
42,normal,for-loop,mazes/042.txt,400,lua,90;180,,curriculum/042_hints.lua,curriculum/042_solution.lua
301,hardcore,event-driven,mazes/h01.txt,300,lua,,45,,curriculum/h01_solution.lua
```

- `pause_at`: 일반 모드에서 타이머가 정지되고 준비 단계가 열리는 시점들 (하드코어는 빈 값)
- `wave_clock`: 하드코어에서 N초마다 웨이브를 강제 투입하는 주기 (일반은 빈 값)
- `solution_file`: 정답 코드 — 회귀 테스트용, 전 스테이지 필수

`timelines.csv` — 1행 = 스폰 이벤트 1개, 결정론적 스케줄 (랜덤 없음):

```csv
stage_id,at,spawn,count,interval
42,0,bug,10,1.5
42,60,attempt-to-index-nil,3,5
```

`enemies.csv`, `items.csv`, `towers.csv`(테크 의존성 `requires` 열), `codex.csv`도 같은 방식.

### 7.3 저장

`love.filesystem`으로 유저 폴더에 JSON 저장: 진행도, 도감, 라이브러리, 인벤토리,
퀵바 구성, `hardcore_cleared`, `perk_tokens`, 하드코어 주력 진영,
스테이지별·**언어별** 베스트 타임 + 리플레이 시드·검증 해시.

## 8. 테스트 전략

기존 love2d-tetris/mario에서 검증한 하네스 패턴 (스크래치패드 별도 LÖVE 프로젝트 + `package.path` 주입):

1. **샌드박스 단위 테스트 (최우선)** — 탈출 시도(io/os/전역 오염), 무한 루프 타임아웃,
   명령 예산 초과가 전부 안전하게 격리되는지. 유저가 임의 코드를 넣는 게임이므로 가장 중요.
2. **전투 시뮬레이션 회귀 테스트** — 각 스테이지의 `solution` 코드로 300초 시뮬레이션 →
   클리어 검증. 스테이지 300개가 쌓여도 자동 검증.
3. **난이도 검증 규칙** — 각 스테이지의 정답 코드는 이전 구간 지식만으로 작성 가능해야 한다 (리뷰 규칙).
4. **에디터 테스트** — 키 입력 시뮬레이션으로 커서/삽입/삭제/한글 주석/퀵바 삽입 검증.
5. **CSV 데이터 무결성 검사** — 파서 단위 테스트 + 참조 검증: `timelines.csv`의 `spawn`이
   `enemies.csv`에 존재하는지, `stages.csv`가 참조하는 미로/정답 파일이 실재하는지,
   `towers.csv`의 `requires`가 유효한 타워 id인지. 데이터가 300스테이지로 불어나도
   깨진 참조를 커밋 전에 잡는다.

## 9. v1 범위와 이후 로드맵

### v1 (코어 수직 슬라이스, 데스크톱)

TD 엔진 + 그리드/미로 + Lua 샌드박스 + 게임 내 에디터 + 스니펫 퀵바 +
아이템=API 해금 시스템 + 테크 의존성 + 코드 크래프트(오버클럭·차지샷) + 밈 도감 +
언어 진영 프레임워크(실행 가능 진영은 Lua 하나) +
일반 모드 스테이지 15~20개 (구간 1~10, 11~20, 21~30 표본) +
하드코어 모드 3~5개 표본 + 클리어 타임 기록·공유 카드 PNG.

### v2 이후 (예약, v1 설계가 막지 않도록만 고려)

- **멀티 언어 진영**: 타워 API를 언어 중립으로 유지 → Python/JS/C# 외부 프로세스 어댑터로
  진영 추가. 진영 선택 UI·보너스·언어별 랭킹은 v1 프레임워크에 이미 있으므로 어댑터만 붙인다.
- **AI 에이전트 모드**: 하드코어 후반 인간 한계 난이도에서 LLM 에이전트가 실시간 코딩 —
  "바이브코딩의 효율 증명"이 최종 목표.
- **모바일**: LÖVE Android/iOS 빌드 + 터치 반응형 UI (퀵바가 모바일 입력의 핵심이 됨).
- **온라인 리더보드**: 클리어 타임 고유 URL 링크 게시, 서버 검증(리플레이 시드·해시), 코드 공개 옵션.
- **커뮤니티 밈**: 유저 제안 밈을 데이터 파일로 수용하는 파이프라인.
- **대전 모드 (PvP)**: Mage Arena가 음성으로 주문을 외치듯, 여기서는 **빠른 타이핑이 곧 실력**인
  1:1 대전. 서로의 타워가 서로의 넥서스를 공격하며, 코드를 더 빠르고 정확하게 작성·수정하는
  쪽이 상대 넥서스를 먼저 부순다. 공격 유닛 편성도 코드로 제어. 하드코어 모드의 실시간 코딩이
  이 모드의 훈련장 역할을 한다. (네트워크 동기화가 필요하므로 온라인 리더보드 이후 단계)

## 10. 성공 기준

1. 코딩을 모르는 사람이 1~10구간을 이탈 없이 통과하고, 11구간에서 처음으로 코드를 타이핑한다.
2. 21~100구간의 각 스테이지가 "새 개념 하나"를 정답 코드에 강제한다 (이전 지식만으로 가능).
3. 하드코어 클리어 타임을 SNS에 공유하는 행동이 실제로 일어난다 (공유 카드 1클릭).
4. 밈 도감을 본 유저가 용어의 실제 의미를 말할 수 있다.
5. 같은 스테이지를 반복한 유저의 클리어 타임이 타이핑 숙달로 단축된다 — 측정 가능해야 한다.
