## 4. 이 프로젝트에서 일하는 방식 (사용자와 합의된 워크플로)

1. **결과 보고·질문은 전부 한글** (사용자 전역 지침).
2. **설계서(스펙) → 사용자 승인 → 구현 계획 → 실행** 순서. 실행은 superpowers의
   subagent-driven-development(태스크별 구현자+리뷰어 게이트, fable 최종 브랜치 리뷰 →
   수정 웨이브 → 재리뷰)를 썼다 — 품질 게이트 유지 권장.
3. **게임의 개성을 해치는 변경은 판단하지 말고 사용자에게 질문** (사용자 명시 지시).
   개성의 핵심: ① 실시간으로 코드/명령을 치는 압박(일시정지 금지 — 슬로우 x0.5만),
   ② 결정론, ③ 코드/명령이 유일한 조작 수단, ④ 학습 포인트 강제(퍼즐 스테이지 옵트인).
   게임명 같은 정체성 결정도 사용자 몫(§1 개명 경위가 선례).
4. 커밋마다 전체 스위트. 뷰 변경은 스크린샷 검증 관례(§5).
5. 밸런스 조정 권한: 그 회차 신규 콘텐츠 행만, 근거를 보고서에 기록, 회귀 통과가 완료 조건.
6. 마무리 체크리스트: 전 스위트+데이터 회귀 → fable 최종 리뷰 → 수정 → 재리뷰 →
   `love2d-serverdev/tools/package.ps1`로 dist 재생성 → push → 이 문서 갱신.

## 5. 반복적으로 밟은 함정

- **헛단언(vacuous assertion)이 이 브랜치에서 4회 적발됐다.** 테스트를 쓰면 ① 게이트 조건이
  실제 참인지 값 추적(예: resist 게이트의 타워 id가 진짜 매칭되는지), ② floor 같은 산술은
  **비정수 입력**으로 구별(10×0.5=5.0은 floor 유무를 못 가른다), ③ 부정 단언("발사 안 함")은
  우연(bullet_speed=0 즉시 소멸 등)이 아닌 원인 분기로 증명.
- **언어서버(LSP)의 "미사용" 진단은 이 프로젝트에서 7회 연속 스테일 오탐이었다**(실사용 중인
  상수·함수·require를 미사용으로 표시). 반면 진짜 갭을 잡은 적도 있으니 무시하지도 말 것 —
  반드시 diff/실코드로 판정. `data/curriculum/*.lua`의 undefined-global `build`/`world`는
  샌드박스 DSL이라 정상, `*_hints.lua`는 빈칸(`______`) 템플릿이라 의도적으로 유효하지 않은
  Lua다.
- **스크린샷 검증**: captureScreenshot에 파일명 문자열을 주면 %APPDATA%로 간다 — 콜백에서
  ImageData:encode 후 io로 절대경로에 쓸 것. 찍은 PNG는 반드시 Read로 육안 확인(허위 검증 보고
  전례 있음). 하네스는 스크래치패드(세션 임시)에만 — 레포 커밋 금지.
- **exe 아이콘이 탐색기에서 옛것으로 보이면** Windows 아이콘 캐시 잔상(F5/재부팅).
  package.ps1이 rcedit 주입까지 한다. dist 삭제 직후 재실행 시 data 복사가 간헐 실패하는 기존
  결함이 있다 — 재실행하면 정상.
- **세션 한도 중단**: 서브에이전트가 죽으면 작업 트리에 부분 작업이 남는다. 같은 에이전트를
  재개(트랜스크립트 유지)하는 것이 가장 정확했고, 재개 시 "기억보다 파일을 다시 읽어라"를
  지시할 것.
- **보고서 서술 부정확 전례 3건** — 산출물은 정상이나 구조 서술이 실파일과 달랐다. 리뷰어는
  보고서를 믿지 말고 재검산할 것.

## 6. 코어 불변 규칙 (전 리뷰에서 확립 — 어기면 회귀가 깨진다)

- **floor·min1은 신규 능력 경로(resist·pair·splash)에만.** 기존 파이프라인(charge 배율)은
  비정수 그대로 — 전역 floor 금지. 복합 시 resist→pair 순서로 각각 floor.
- **결정론**: 주기 행동(grow/dash/phase/cron)은 스폰·등록 시각 기준 순수 산술 재계산,
  타이브레이크는 스폰 순, love.timer 금지(시간은 battle clock).
- **은신(phase) 제외는 단일 지점**(api.refresh 스냅샷 필터 — world.* 전부 공유). 단, **battle
  내부의 전략 선택(selectTarget)은 사거리 필터까지 적용**(전역 아님 — Wave D 확정).
- **실효 이동 속도는 Enemy:effectiveSpeed() 단일 훅**(dash×slowfield 곱).
- **abilities는 `;` 분리 토큰 완전 일치**(콜론 인자). 부분 문자열 :find 금지.
- 미로: 12×16, B≥6, **모든 건설칸은 스폰 실경로를 사거리(120px, CELL 32)로 교전 가능**(죽은
  슬롯 금지), 같은 테마 미로 상이, 스폰 열=1행 통로. 타임라인: 마지막 ≥240s, 공백 ≤39s
  (경계값 금지), countdown 15~30.
- **Lua 진영 불변**: autoAttack은 opts.autoAttack==true(셸 스테이지)에서만. 셸 타워는 오버클럭
  미적용(발사 속도 하한 고정 = 최적화된 Lua 타워보다 불리 — 밸런스 전제).
- 데드락 pair 경감은 짝이 필드에서 사라지면(사망·도달) 해제 — **집중 사격(희생자 선정)이
  정답**. "분산 필수" 서사는 실측으로 반증되어 정정됐다(991d586) — 되돌리지 말 것.
- 세이브: 새 저장 필드 추가를 피해 왔다. identity는 "love2d-codedefense" 고정(§1).
