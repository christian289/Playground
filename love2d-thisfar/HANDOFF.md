## 2. 스펙에 있지만 아직 안 한 것 (다음 회차 후보)

### 명시적 비범위(스펙에 "다음 회차"로 고정)
- **외부 제어 어댑터** (Wave D 스펙 §4): `--cmdfile <경로>` 기동 옵션 → 파일 tail 폴링 → 한 줄씩
  `shell:exec` → 결과를 `<경로>.out`에 append. "Claude Code가 파일에 명령을 써서 게임을
  플레이"하는 데모가 목표. `src/shell.lua`가 순수 "문자열 in→out"이라 어댑터는 얇다.
  하드코어 모드에서는 비활성(공정성).
- **하드코어 모드(Wave C)**: 50단계, 클리어 타임 계측. + 클리어 타임 인증 카드 PNG 생성·공유
  텍스트 클립보드 복사 (0.1 설계서 9장).
- 밈 도감 심화(오류 실례 텍스트 수집), 아이템 확장(CPU 코어 증설=예산 증가, 공용 라이브러리 탭),
  언어 진영 확장(Python/JS/C#는 외부 프로세스 어댑터로 v2), 타워 매도(sell)·진행도 리셋 메뉴,
  타워 업그레이드, 스테이지 타일 틴트 변주, 도감 코드 예제 실행 — 전부 명시적 이연
  (CLAUDE.md "다음 단계 (0.2+)" 절 참고).

### 리뷰에서 이연된 결함/개선 (작을수록 위, 전부 비차단 판정)
- **split 자식 y좌표 셀 중심 스냅**: `src/battle.lua`의 분열 코드가 `child.x`만 부모 실좌표로
  재정의하고 y는 셀 중심(최대 32px 수직 팝). 0.1부터 있던 특성이나 Wave B(포크 밤·커널 패닉)로
  노출 빈도 급증. `child.y = e.y` 한 줄이면 되지만 **시뮬 변경**이라 스테이지 16·20 퍼즐
  회귀(솔루션 클리어·naive 패배) 재검증+필요 시 재튜닝과 묶어서 할 것.
- **은신(phase) 중 HP바·감속 점이 불투명**: 스프라이트는 α0.25인데 부속 UI가 위치를 노출
  (`states/play.lua`). 뷰 전용 수정.
- **world.oldest가 에디터 클릭으로 안 열림**: `src/editor.lua`의 `tokenAt` 패턴이 `.`을
  안 잡아서 `world.oldest` 식별자가 함수 사전 클릭 매칭 불가(목록 클릭은 됨).
- **on_spawn 스냅샷의 speed가 스폰 순간 dash 창 미반영** (`api.plainSnapshot`) — 관측 불일치만.
- **splash 기준 데미지 = 주 타겟 판정 후 값**: 주 타겟이 경감 대상이면 그 감쇄가 낙폭 기준치에
  전파돼 피해자 자신의 경감과 복합될 수 있음(결정론적, 회귀 검증됨). 문서 한 줄 명시 or
  원시 데미지 기준으로 변경 중 결정 필요.
- **`src/projectile.lua`의 `resistMult or 0.5` / `pairMult or 0.4` 기본값**이 `battle.lua`
  상수(RESIST_MULT/PAIR_MULT)를 복제 — 상수 바꿀 때 두 곳 드리프트 주의.
- race-cond hp 90(3배 조정)이 "잡몹" 서사와 어긋난다는 참고 메모(의도적 조정, 근거는 아래 §5).
- 구형 0.2 이연(RT/LF 웨이브): setScript 실패 시 고아 타워 비환불, Ctrl+숫자 버튼 누수,
  scriptError 위치 5px 겹침, stageselect/codex 마우스 일관성, 도감 빈 목록 cursor=0 등 —
  전부 소소한 폴리시. 원장이 없으면 해당 파일에서 재발견 가능.

## 3. 이 프로젝트에서 일하는 방식 (사용자와 합의된 워크플로)

1. **결과 보고·질문은 전부 한글** (사용자 전역 지침).
2. **설계서(스펙) → 사용자 승인 → 구현 계획 → 실행** 순서. 스펙은
   `docs/superpowers/specs/`, 계획은 `docs/superpowers/plans/`에 날짜 접두 파일로.
   실행은 superpowers의 subagent-driven-development(태스크별 구현자+리뷰어 게이트,
   fable 최종 브랜치 리뷰 → 수정 웨이브 → 재리뷰)를 썼다 — 강제는 아니나 품질 게이트
   (태스크별 독립 리뷰, 최종 리뷰)는 유지 권장.
3. **게임의 개성을 해치는 변경은 판단하지 말고 사용자에게 질문** (사용자 명시 지시).
   개성의 핵심: ① 실시간으로 코드를 치는 압박(일시정지 금지 — 슬로우 x0.5만),
   ② 결정론(같은 배치·코드=같은 결과), ③ 코드/명령이 유일한 조작 수단,
   ④ 각 스테이지는 "대응 패턴 없이는 지고 있으면 이기는" 출제(학습 포인트 강제).
4. 커밋마다 전체 스위트 실행. 뷰 변경은 스크린샷 검증이 관례(아래 §4).
5. 밸런스 조정 권한 프로토콜: 그 회차 신규 콘텐츠 행만, 근거를 보고서에 기록,
   회귀 통과가 완료 조건. 기존 행·기존 스테이지 불변.
6. 최종 마무리 체크리스트: 전 스위트+데이터 회귀 → fable 최종 리뷰 → 수정 → 재리뷰 →
   `tools/package.ps1`로 dist 재생성 → push.

## 4. 반복적으로 밟은 함정 (그대로 또 밟기 쉬움)

- **헛단언(vacuous assertion)이 이 브랜치에서 4회 적발됐다.** 테스트를 쓰면
  ① 게이트 조건이 실제 참인지 값을 추적하고(예: resist 게이트 `target.abilities.resist ==
  tw.def.id`가 진짜 매칭되는지), ② floor 같은 산술은 **비정수 입력**으로 구별하라
  (10×0.5=5.0은 floor 유무를 못 가른다), ③ "발사 안 함"류 부정 단언은 우연(bullet_speed=0
  즉시 소멸 등)이 아닌 원인 분기로 증명하라.
- **언어서버(LSP) 진단은 절반이 오탐/스테일이다.** `data/curriculum/*.lua`의
  `undefined-global build/world` 경고는 샌드박스 DSL이라 정상. `*_hints.lua`는 빈칸(`______`)
  채우기 템플릿이라 **의도적으로 유효하지 않은 Lua**다. 시그니처 변경 직후 redundant-parameter,
  실제로 쓰이는 상수의 unused-local 등 스테일 오탐이 여러 번 있었다 — 진단만 믿고 "고치지"
  말고 반드시 diff/실코드로 검증.
- **스크린샷 검증**: `love.graphics.captureScreenshot`에 파일명 문자열을 주면 유저 폴더
  (%APPDATA%)로 가버린다. 콜백에서 ImageData:encode 후 `io`로 **절대경로**에 쓸 것.
  찍은 PNG는 반드시 Read로 열어 육안 확인(허위 검증 보고 전례 있음 — 재캡처 없이 옛 파일
  복사한 서브에이전트가 있었다).
- **오토플레이/스크린샷 하네스는 스크래치패드(세션 임시)에 만들었다** — 새 세션에는 없다.
  패턴: 미니 LÖVE 앱 폴더(conf.lua+main.lua)에서 `require`로 states/battle을 직접 구동.
  레포에 커밋하지 말 것.
- **exe 아이콘이 탐색기에서 옛것으로 보이면** Windows 아이콘 캐시 잔상이다.
  `tools/package.ps1`이 rcedit로 PE 리소스 주입까지 한다(실패 시 throw). F5/재부팅으로 해결.
- **세션 한도 중단**: 서브에이전트가 한도로 죽으면 작업 트리에 부분 작업이 남는다.
  같은 에이전트를 재개(트랜스크립트 유지)하는 것이 가장 정확했고, 재개 시 "기억보다 파일을
  다시 읽어라"를 지시할 것.
- **stageselect 언락이 전역 `id-1` 참조였다** — 불연속 id(셸 101번대)에서 영구 잠김.
  Wave D Task 3이 "진영 내 이전 항목" 기준으로 고치는 계획이다. Wave D가 미완이라면 이
  항목이 됐는지 반드시 확인.

## 5. 코어 불변 규칙 (전 리뷰에서 확립 — 어기면 회귀가 깨진다)

- **floor·min1(`math.max(1, math.floor(x))`)은 신규 능력 경로(resist·pair·splash)에만.**
  기존 데미지 파이프라인(charge 배율)은 비정수 그대로 — 전역 floor 금지. 근거: 기존
  스테이지 시뮬 결과 불변이 최우선(회귀 20종이 이를 증명). 복합 시 resist→pair 순서로
  각각 floor(순서가 결과를 바꿈 — battle.lua에 주석 있음).
- **결정론**: 주기 행동(grow/dash/phase/cron)은 전부 스폰·등록 시각 기준 순수 산술
  재계산(상태 누적 금지), 타이브레이크는 항상 스폰 순, `love.timer` 금지(시간은 battle clock).
- **은신(phase) 제외는 단일 지점**: `api.refresh`의 스냅샷 빌드에서 한 번 걸러
  world.* 전부가 공유. 새 타겟팅 코드를 추가하면 같은 필터를 태울 것.
- **실효 이동 속도는 `Enemy:effectiveSpeed()` 단일 훅**: dash×slowfield가 여기서 곱해진다.
  속도를 만지는 새 기능은 반드시 이 훅에 곱셈으로 참여.
- **abilities는 `;` 분리 토큰 완전 일치**(콜론 인자 `resist:printer`). 부분 문자열
  `:find` 검사 금지(split/split2 오탐 전례).
- 미로: 12×16, 건설칸 ≥6, **모든 건설칸은 스폰 실경로를 사거리(프린터 120px, CELL 32)로
  교전 가능**(죽은 슬롯 금지), 같은 테마 3장 상이, 스폰 열=1행 통로(`d.validate` 기계 검증).
  타임라인: 마지막 스폰 종료 ≥240s, 인접 공백 ≤39s(경계값 금지), countdown 15~30.
- 세이브 호환: 새 저장 필드 추가를 피해 왔다(별점=bestHP 파생, 프로필=기존 데이터 집계).
  새 필드가 필요하면 구세이브 로드 방어를 함께.

## 8. Wave D를 이어받는 경우의 계약 (진행 중이라면)
